# 给 AI 的看板规矩（提示词）

把下面这段发给每一个要用看板的 AI：写进 Claude Code 的 `CLAUDE.md`、Codex / Gemini CLI 的 `AGENTS.md`，或者放在每次提示词的开头。按自己的情况改名字和路径。

```
从今天起，几个 AI 要在同一张看板上协同干活。

为什么：以前各干各的，互相不知道对方在做什么。两个 AI 可能同时干同一件事；一个断了（额度用完、凭据过期、超时），另一个接不上；事后也查不到哪一步是谁做的、为什么出错。看板解决这三个问题：谁在做什么、做到哪一步、产物在哪，所有人都看得到。

命令是 board（没有就用 python3 <路径>/board.py），用法 board help。你的名字写在 BOARD_ACTOR 里，别人看流水时就知道哪条是你记的。

只记工作上的事：交代给你的任务，你为这件事做的每个关键操作和结果。闲聊、私事、人设和情绪都不记。

1. 接到一件工作，动手前先 board list，看有没有别人已经在做。
2. 看板上没有这件事，就先 board add "标题" 建一条，再 board claim 编号 认领；认领失败说明别人在做，不要动，报告给人。
3. 每做完一个关键步骤，记一条：board log 编号 "做了什么、结果是什么" "产物路径"。一条写一件事，写结果和数字，不写感想。
4. 这件事结束时必须标状态，三选一：board done 编号 "结果"、board stuck 编号 "卡在哪"、board drop 编号 "为什么放弃"。不能做一半就没了下文。
5. 中途断了，下次接手先 board show 编号，读完之前的流水，从断点接着做，不要从头再来。接别人的也一样。
6. 别人认领的事不准改状态。对方超过 2 小时没动静（列表里会标 ⚠），也要先问人，同意了才能 board release 编号 "原因" --force 接过来。
7. 不属于任何任务、但动了东西的操作（改配置、装软件、删文件），用 board note "做了什么" 记一条。
8. 口令、密钥、个人隐私都不写进看板。产物只写路径，不贴全文。
9. 连不上看板时，先读最近一次导出的镜像文件，照常干活，连上以后把漏记的补上。
10. 看板只记「事」和「过程」。做完得出的结论、教训、决定和理由，写进你们的知识库或文档，不写在看板里。

收到后用一句话复述你理解的用法，然后跑一次 board list。
```
